# UCTO Glossary

## Purpose
Single source of truth for UCTO terminology. Prevents drift across 17+ documentation files.

---

### Agent
An AI service that performs a specific role in the UCTO platform. The 6 core agents are: Business Analyst, Developer, Tester, Compliance, UI/UX Expert, Solutions Architect.

### Agent Run
A consumable unit of platform usage. Incremented each time the orchestration service publishes a `trigger` event to any agent topic. See `usage_metering_design.md` for exact rules.

### BA Clarification
The process by which the Business Analyst agent asks the customer follow-up questions to refine ambiguous requirements. Capped at 3 rounds per requirement batch. See `state_machines.md` for the full state machine.

### Design Sprint
The phase in a sprint lifecycle where the UI/UX Expert agent generates screens from approved requirements. The second ceremony in the UCTO sprint cycle.

### Founders, Developers, Viewers
Customer sub-roles within a project:
- **Founder**: Creates projects, approves screens, views outputs. Maximum authority.
- **Developer**: Accesses generated code, runs tests, deploys. Cannot approve screens.
- **Viewer**: Read-only access to requirements, screens, and outputs.

### Gate
A quality and compliance checkpoint in the screen workflow. Three gates:
1. **Gate 1**: Customer approval of screens (before development)
2. **Gate 2**: Compliance Agent validation (privacy, accessibility)
3. **Gate 3**: Tester Agent validation (UI flows match approved screens)

### Project
A container for one application being built with UCTO. Has an owner (Founder), members (Founders, Developers, Viewers), and a subscription tier.

### Project Member
A user assigned to a project. Has one of three roles: Founder, Developer, or Viewer. Membership is tier-scoped (Free: 1 project, Startup: 5 projects, Growth: 50 projects).

### Requirement
A single functional or non-functional specification for the project. Belongs to a project. Managed by the BA agent through the clarification lifecycle.

### Requirement Batch
A group of requirements processed together in one sprint. Submitted for BA clarification as a unit.

### Screen
A visual mockup of one app screen. Generated by the UI/UX Expert agent. Goes through approval lifecycle: Draft → InReview → Approved/Rejected/ChangesRequested → FinalApproved.

### Screen Package
A batch of screens submitted together for customer review. Rejection can be per-screen or batch-level.

### Solutions Architect Agent
The agent responsible for suggesting integrations, reviewing architecture, and recommending technology choices. Full name is "Solutions Architect" — never abbreviated to "Architect."

### Sprint
A time-boxed cycle (default: 1 week) in the UCTO agile process. Has 8 ceremonies: Planning, Design Sprint, Architecture Review, Compliance Check, Development Sprint, Testing Sprint, Sprint Review, Retrospective.

### Tier
A subscription level defining platform access. Tiers: Free (5 runs, 1 project), Startup (50 runs, 5 projects), Growth (200 runs, 50 projects), Enterprise (unlimited).

### Traceability Artifact
Any output that links a requirement to an agent action and a test result. Examples: audit log entries, RTM records, compliance check results.

### Usage Limit
The maximum number of agent runs a tier allows per month. Enforced by the Usage Metering service. Exhaustion triggers graceful degradation (read-only mode).

### UCTO Admin
Platform operator role with full access: user management, agent configuration, audit log review, system settings. Distinct from customer roles (Founder, Developer, Viewer).

### Backend
Spring Boot (Java 25) application providing REST APIs for auth, projects, requirements, agents, audit, compliance, subscriptions, and screens.

### Frontend
Flutter + BLoC application delivering the web portal (MVP) and mobile apps (Phase 2). Strictly separate `blocs/`, `models/`, `ui/` layers.

### Redis Pub/Sub
Message broker used for MVP agent orchestration. Topics follow `agent.<type>.<action>` naming. Phase 2 may migrate to RabbitMQ.

### S3-Compatible Storage
The object storage abstraction used for screen images, code artifacts, and compliance reports. Concrete implementation may be Backblaze, Wasabi, or AWS S3.

### Audit Log
An immutable record of all user and agent actions. Captures: who, what, when, and outcome. Required for DPDP/GDPR compliance.

### DPDP
Digital Personal Data Protection Act (India). India's data protection regulation. Applies to all UCTO user data from Indian residents.

### GDPR
General Data Protection Regulation (EU). EU data protection regulation. Applies to UCTO users from the European Union.
